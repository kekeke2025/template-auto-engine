📝 迭代文档自动记录规则
🧠 核心机制：每次回复用户前，必须先复盘本轮对话内容，判断是否有需要记录的信息。如有，先更新迭代文档，再回复用户。无需用户明确指令。

一、每次回复前必须检查的6个维度

1. 【任务进展】有没有任务做完了？有没有新的进展？
   → 更新：任务拆解表状态 + 里程碑

2. 【问题/踩坑】有没有遇到bug、报错、异常、失败？
   → 更新：Badcase 记录（问题描述 + 根因 + 解决方案）

3. 【方案变更】有没有改需求、改方案、调整范围？
   → 更新：变更记录表 + 范围界定（如有必要）

4. 【技术决策】有没有做技术选型、架构决策？
   → 更新：技术方案章节

5. 【风险发现】有没有发现潜在风险、隐患、担忧？
   → 更新：风险预判表

6. 【用户反馈/产品讨论】有没有用户提出的产品意见、交互问题、逻辑讨论？
   → 更新：变更记录表（标注讨论类）

二、更新动作要求
1. 必须在回复用户之前完成文档更新
2. 更新后在回复末尾用一行小字说明：「📝 已记录：xxx」
3. 记录要具体：不要只写"有bug"，要写清楚什么bug、原因是什么、怎么解决的
4. 如果不确定归到哪一类，优先记到 Badcase 或变更记录
5. 宁多勿少：不确定要不要记的，先记下来

三、文档位置规则
- 迭代文档统一放在 docs/ 目录下
- 命名格式：迭代-vX.X-名称.md
- 当前进行中的迭代只有一个，自动识别最新的"进行中"状态的迭代
- 如果没有进行中的迭代，检测到新项目启动时自动创建

四、执行原则
- 不靠关键词触发，靠内容判断
- 每次回复前强制自检6个维度
- 记录动作不打断主对话，在后台完成
