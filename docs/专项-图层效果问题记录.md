## 二、Badcase 记录

### BC-001：图层样式完全不生效（只有透明度有效果）

**问题描述**：上传带图层样式的 PSD 后，渲染结果只有透明度（混合模式）有效果，描边、投影、外发光、颜色叠加等样式完全不显示。

**根因分析**：三个问题叠加：
1. **前端解析路径错误**：`extractLayerStyle` 从 `layer.additionalLayerInfo.effects` 读数据，但 ag-psd v31 的 effects 直接在 `layer.effects` 上（Layer extends LayerAdditionalInfo），导致所有 effects 数据都读不到。
2. **上传时字段丢失**：前端上传时 map 图层数据，漏掉了 `layerStyle`、`blendMode`、`children` 字段，即使解析到了也传不到后端。
3. **画布扩展未修正位置**（已修）：投影、外发光、外描边会扩展画布，但合成时按原图层尺寸计算，导致扩展部分被裁掉。

**解决方案**：
1. 修正 `extractLayerStyle` 的 effects 路径：`layer.effects || layer.additionalLayerInfo?.effects`
2. 修正 `fillOpacity` 路径：`layer.fillOpacity`（0-255 → 除以 255）
3. 上传时补上 `layerStyle`、`blendMode`、`children` 字段
4. 去掉 `_replaced` 条件限制，所有有 `layerStyle` 的图层都应用样式
5. `applyLayerStyles` 返回 `{ buffer, offsetX, offsetY, width, height }`，调用方用实际尺寸计算合成位置
6. 外描边/居中描边改为扩展画布方式

**修复文件**：
- `frontend/src/utils/psdParser.ts` — 修正 effects 路径 + fillOpacity 单位
- `frontend/src/pages/template/upload.tsx` — 补上 layerStyle/blendMode/children 字段
- `backend/src/template/layer-style.service.ts` — 返回值重构 + 描边扩展画布
- `backend/src/template/image-render.service.ts` — 去掉 `_replaced` 限制 + 适配新返回值

**发现时间**：2026-09-14
**修复时间**：2026-09-14
**状态**：已修复，待验证（需重新上传 PSD）

### BC-002：描边/外发光效果极淡几乎看不见

**问题描述**：描边、外发光效果非常淡，几乎看不见，颜色叠加和投影（主体）有效果。

**根因分析**：
`dilateAlpha`（alpha 膨胀函数）之前只做了高斯模糊，没有做阈值二值化。导致膨胀后的 alpha 是渐变的（边缘很柔和），和原始 alpha 相减后，描边的 alpha 值非常低，几乎透明。

**解决方案**：
- `dilateAlpha` 改为 `blur + linear 阈值` 的形态学膨胀（模糊后提高对比度，让边缘变成硬边）
- 阈值设为 0.3（低于阈值变透明，高于阈值变不透明），近似形态学膨胀效果
- `erodeAlpha` 走反向膨胀，同步修复

**影响范围**：描边（外/内/居中）、外发光（走投影路径）、内发光、内阴影的 choke、投影的 spread

**修复文件**：
- `backend/src/template/layer-style.service.ts` — `dilateAlpha` / `erodeAlpha` 重写

### BC-003：投影 spread（扩展）没效果

**问题描述**：投影有出来，但边缘很柔和，spread（扩展/硬度）参数没起作用。

**根因分析**：
之前的 `applyDropShadow` 完全没处理 spread 参数，直接用 size 做模糊。spread 在 PS 里是百分比（0-100%），控制投影边缘硬度：spread=0% 完全柔和，spread=100% 硬边。

**解决方案**：
- spread 先转成像素：`spreadPx = size * spread%`
- 先把 alpha 膨胀 spreadPx（形态学膨胀），再做剩余 `size * (1-spread%)` 的模糊
- 模糊半径随 spread 增大而减小：`blurSize = size * (1 - spread%)`

**修复文件**：
- `backend/src/template/layer-style.service.ts` — `applyDropShadow` 增加 spread 处理

- 未修改的图层 → 直接用 PSD 原始 imageData（样式已包含在像素中，100% 准确）
- 被替换的图层（`_replaced: true`）→ 重新渲染内容 + 重新应用 layerStyle
- 好处：性能好、未修改的效果最准
- 文件：`image-render.service.ts` / `compositeImageLayer`

- 不管图层有没有被替换，混合模式都是图层和底图的关系
- 通过 `composite.blend` 参数传递给 sharp
- 文件：`compositeImageLayer` / `compositeTextLayer`

**3. ag-psd effects 数据路径**
- 图层样式数据在 `layer.additionalLayerInfo.effects` 上
- 不是在 `layer.effects` 上（虽然类型定义里 Layer 也有 effects 字段）
- 已做双路径兼容

## 五、技术分析：为什么会有效果问题？

### 5.1 当前渲染流程
```
PSD 文件 → ag-psd 解析 → 提取图层 imageData + 样式参数
                           ↓
                    逐层渲染（sharp composite）
                           ↓
                    未修改图层 → 直接合成 imageData（效果完整）
                    已修改文字层 → SVG 重新渲染（可能丢失图层样式）
                    已修改图片层 → 新图片 resize 后合成（可能丢失图层样式）
```

### 5.2 效果丢失的根本原因

| 场景 | 效果是否丢失 | 原因 |
|------|-------------|------|
| 未修改的图层 | ❌ 不丢失 | 用的是 PSD 原始 imageData，像素已经包含了所有效果 |
| 未修改的文字层 | ❌ 不丢失 | 同上 |
| 被替换的文字层 | ⚠️ 部分丢失 | SVG 重新渲染，字号位置可以对齐，但图层样式（描边/阴影等）没了 |
| 被替换的图片层 | ⚠️ 部分丢失 | 新图片直接 resize 合成，图层样式和混合模式没了 |
| 带混合模式的图层 | ⚠️ 可能丢失 | sharp 默认用 over 模式，需要手动指定 blend |

### 5.3 核心矛盾
**用户想修改内容（文字/图片），又想保留 PSD 的所有视觉效果。**

但只要重新渲染内容，就必然涉及"效果复刻"的问题——PSD 的图层样式是 Photoshop 私有的，第三方渲染引擎不可能 100% 还原。

### 5.4 应对策略（建议）
1. **优先级**：先确认哪些效果是真的有问题，再按影响程度排序修复
2. **策略选择**：
   - 能用原始 imageData 的就用原始的（最快最准）
   - 必须重绘的，优先用 sharp 原生能力实现（blend 模式、模糊等）
   - 复杂样式用 SVG filter 兜底
3. **兜底方案**：如果某个效果实在实现不了，在文档里明确标注"不支持"，让用户用替代方案
