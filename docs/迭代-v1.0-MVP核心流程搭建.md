## 一、迭代背景

### 1.1 平台底层逻辑 & 核心目的

**解决的核心痛点：**
> 同一个内容需要同时适配公众号、小红书、抖音、视频号等多个平台的不同尺寸封面，重复制作效率极低。

**底层逻辑：**
```
PSD模板（设计师做好） → 解析图层（识别可编辑的文字/图片） → 绑定多尺寸规格
                                                              ↓
用户输入替换内容（文字+图片） → 一键批量渲染 → 生成所有尺寸的图片 → 打包下载
```

**核心价值主张：**
- 制作效率提升 80% 以上
- 一次模板配置，无限次复用
- 非设计人员也能快速出图

### 1.2 目标用户
- 新媒体运营人员（多平台内容分发）
- 电商美工（商品图多尺寸批量生成）
- 内容创作者（封面图快速制作）
- 设计团队（模板标准化、降低重复劳动）

### 1.3 驱动来源
- 业务驱动：解决内部/行业普遍存在的多尺寸封面重复制作痛点
- 验证目标：验证"模板化批量出图"模式的可行性和用户价值

## 四、技术选型决策

### 4.1 前端技术栈
| 技术 | 选型 | 选择理由 |
|------|------|----------|
| 框架 | React 18 | 生态成熟，组件库丰富，团队熟悉 |
| 语言 | TypeScript | 类型安全，降低维护成本 |
| 构建工具 | Vite | 启动快、热更新快，开发体验好 |
| UI 组件库 | Ant Design | 企业级组件库，表单/表格等组件完善 |
| 状态管理 | Zustand | 轻量、API 简洁，比 Redux 简单 |
| 路由 | React Router v6 | React 生态标准路由方案 |
| HTTP 客户端 | Axios | 拦截器、取消请求等功能完善 |

### 4.2 后端技术栈
| 技术 | 选型 | 选择理由 |
|------|------|----------|
| 框架 | NestJS | 模块化架构，依赖注入，适合中大型项目 |
| 语言 | TypeScript | 前后端语言统一，类型共享 |
| 认证 | JWT + Passport | 无状态，水平扩展方便 |
| ORM | TypeORM | NestJS 官方推荐，TypeScript 友好 |
| 数据库 | MySQL（v1.0 用 Mock 替代） | 关系型数据库，适合结构化数据 |
| 缓存 | Redis（预留） | 会话缓存、生成任务队列 |
| 文件存储 | OSS（预留，v1.1 对接） | 阿里云 OSS，稳定可靠 |
| 图片处理 | MCP 插件（预留，v1.1 对接） | 专业 PSD 解析和渲染 |

### 4.3 关键架构决策

**决策1：v1.0 用 Mock 数据，不接数据库**
- 理由：快速验证产品流程，降低启动成本，零依赖即可运行
- 影响：后续接数据库需要重构数据层，但 v1.0 代码已预留实体结构

**决策2：前后端分离架构**
- 理由：独立部署、独立迭代，前端可对接不同后端
- 接口规范：RESTful API，统一前缀 `/api/`

**决策3：端口配置**
- 前端：5173（Vite 默认）
- 后端：3002（避开常用的 3000/3001，减少冲突）

## 八、遇到的问题 & 解决方案（Badcase）

| 问题类型 | 问题描述 | 解决方案 |
|----------|----------|----------|
| 环境问题 | Windows PowerShell 默认禁止 npm 执行脚本 | 用 npm.cmd 调用，或设置 ExecutionPolicy |
| 跨域问题 | 前端请求后端接口报 CORS 错误 | 后端 CORS 配置改为 `origin: true`，允许所有来源 |
| 端口冲突 | 3000/3001 端口被其他程序占用 | 前端端口改为 5173，后端端口改为 3002 |
| 数据库依赖 | 开发阶段需要安装 MySQL 才能启动后端 | 移除数据库依赖，所有数据改用 Mock 模拟 |
| 登录问题 | 前端登录报 Network Error | 修复后端 CORS 配置，确保前后端都正常启动 |
| 路由问题 | 新增页面无法访问 | 补充 App.tsx 路由配置，完善路由守卫逻辑 |
